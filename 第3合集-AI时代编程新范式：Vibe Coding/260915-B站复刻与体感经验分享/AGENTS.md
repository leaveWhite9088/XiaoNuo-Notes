# AGENTS.md

## 项目目的与边界

这个项目用于制作一期 B 站合作视频：让 10 个大模型分别用两种方式复刻 B 站首页，再统一比较页面效果、关键操作、稳定性和代码质量。

- `one-shot/` 保存“一次性指令直出”的冻结成品。
- `adversarial/` 保存“对抗性审查多轮结果”的冻结成品。
- `evaluation/` 保存统一采集证据、评分结果、静态榜单和实机演示导演台。
- 本项目不负责发布视频、上传 B 站、修改真实 B 站数据，也不把单次样本成绩解释为模型的长期能力排名。

除非用户明确要求重跑某个实验，`one-shot/` 和 `adversarial/` 下的 20 个参赛样本均视为冻结输入。评测、演示和修复导演台时，禁止修改参赛样本来改善分数或兼容性。

## 规则继承

本文件位于项目根，对本项目全部目录生效。当前未发现本项目上级目录或子目录中有其他适用的 `AGENTS.md`。

- 平台级、用户级和调度规则仍然生效，但不要复制到本文件。
- 如果以后在子目录新增更近的 `AGENTS.md`，该文件只补充该子目录的特殊规则，不要重复项目根规则。
- 修改本文件属于项目基线变更，必须先向用户说明拟改内容、影响范围和验证方式，并取得明确授权。

## 权威来源

处理任务前，按任务类型读取对应文件：

- 实验目标、两种方式的会话约束和模型清单：`提示词与要求.md`。
- 正式端口规划和实验启动约束：`启动要求.md`。
- 最终分数、六项得分、公开优缺点和真实体感：`evaluation/data/results.json`。
- 直接打开静态榜单时使用的同步数据：`evaluation/data/results.js`。它必须与 `results.json` 逐字段一致。
- 实机导演台的 20 个启动适配、真实端口和固定命令：`evaluation/data/live-manifest.json`。
- 实机浮窗的逐样本观察建议：`evaluation/data/live-tips.json`。
- 评分复核记录与全量启动结果：`evaluation/internal/score-audit.json`、`evaluation/internal/live-smoke.json`。
- 榜单和导演台的使用方法：`evaluation/README.md`。

`启动要求.md` 记录实验规划端口；部分保留样本的实现使用了其他端口。启动实机导演台时，以 `evaluation/data/live-manifest.json` 中已经验证过的实际配置为准。发现两者不一致时，报告差异，不要擅自修改参赛样本或规划文档来强行统一。

## 目录职责

### `one-shot/` 与 `adversarial/`

- 每侧必须保留相同的 10 个模型目录。
- 每个模型只保留一个有效或按用户口径封账的样本。
- 禁止为了演示、截图、修测试或提高分数而改写冻结样本。
- 禁止移动模型目录、增加二层协议目录或把临时试跑留在项目内；这类结构变化必须先获用户确认。
- 需要运行样本时，优先通过 `evaluation/runner.mjs` 复制到临时目录后启动。

### `evaluation/`

- `index.html`、`app.js`、`styles.css` 是可离线打开的静态榜单。
- `live.html`、`live.js`、`live.css` 是逐个操作作品的现场导演台。
- `server.mjs` 只在 `127.0.0.1:4399` 提供导演台和受限控制接口。
- `runner.mjs` 只按 `live-manifest.json` 白名单准备、启动和停止一个作品。
- `assets/`、`evidence/`、`blind/` 和 `internal/` 是评测证据或内部复核材料，不是参赛源码。
- `/tmp/bili-live-showcase-cache/` 是可删除、可重建的演示缓存，不是正式结果源。缓存中的改动不得回写参赛目录。

## 两种实验方式

公开界面统一使用以下名称：

- `one-shot`：一次性指令直出。
- `adversarial`：对抗性审查多轮结果。
- 两种结果之差：多轮审查带来的分数变化。

面向普通观众的页面不要显示内部键名、代理编排、额度、封账、代跑、协议状态、P0/P1/P2、JSON、API 或 iframe 等实现术语。内部代码和数据键可以保留英文，但用户可见文案必须自然、具体、一次读懂。

两种方式的总执行时间均控制在约 30 分钟。对抗审查达到时间后以当前结果收敛，不允许无限迭代。若将来重跑实验，必须沿用 `提示词与要求.md` 中的会话数量、写入权限和停止条件；不要把导演台或统一评审团队当成参赛模型的额外开发机会。

## 评分与公开文案

总分为 100 分：视觉还原 35、核心流程 30、操作完成度 15、稳定性 10、内容真实性 5、代码质量 5。

- 不得为了让榜单差距更明显而调整分数。
- 视觉分来自匿名评审的中位数；功能判断以统一浏览器证据为准；代码质量来自只读代码审查。
- 播放器外观不代表视频可播放。判断真实播放时必须观察 `currentTime` 持续增长，并验证暂停和继续。
- 搜索框、分类按钮或详情入口存在，不等于对应操作有效；必须观察内容或页面状态实际变化。
- 修改 `results.json` 后必须同步生成 `results.js`，并验证两份数据完全一致。
- 修改公开评价或建议时，保留事实、分数和不确定性。确认过的缺陷可以直接陈述；证据不足时写成“可以重点看看”之类的现场观察动作。

## 实机导演台

用户正常入口是双击 `evaluation/启动实机演示.command`。重复双击时应复用已经运行的导演台，而不是再启动一个服务。

导演台必须满足：

- 同一时间最多运行一个作品。
- 切换模型或方式时，先停止旧作品并确认端口释放，再启动新作品。
- 页面刷新后恢复后台仍在运行的作品、对应评分和保活状态。
- 停止、启动失败或恢复失败时，必须回收运行器拥有的进程；不能只清空界面。
- 只使用后台状态确认的 `frontUrl` 打开作品，不在前端自行推导端口。
- 原作品拒绝嵌入时，可以提供“单独打开作品”备用入口；备用页面不承诺显示评分浮窗。
- 评分浮窗必须与当前作品和方式一致，支持折叠、拖动，并显示总分、排名、六项分数、相对均值、优缺点、真实体感和三条现场建议。

`evaluation/internal/live-smoke.json` 记录了 20 个样本的全量启动检查。修改运行器、清单、启动脚本或作品切换逻辑后，不能只验证一两个样本；必须重新执行 20 项启动、HTTP 200、停止回到空闲和端口释放检查。

## 安全边界

- 禁止把用户提供的模型密钥、令牌、登录凭据或 `.env` 内容写入项目、日志、截图、榜单或汇报。
- 本地控制接口只接受白名单样本 ID；禁止接受网页传入的命令、工作目录、环境变量、任意 URL 或任意端口。
- 控制服务必须只监听 `127.0.0.1`，并继续校验 Host、Origin、随机令牌和 JSON 请求类型。
- 静态服务只能公开导演台需要的页面、样式、公开评分和图片。禁止公开 `internal/`、`evidence/`、`blind/`、运行器源码或项目其他文件。
- 子进程只继承运行必需的系统环境。禁止把模型服务密钥、认证令牌或个人配置传给参赛项目。
- 只终止运行器自己创建并能核验身份的进程组。端口被陌生程序占用时，必须报错并让用户处理，禁止按端口直接杀进程。
- 安装依赖、创建数据库或产生运行状态只能发生在临时副本。禁止通过符号链接、相对路径逃逸或启动脚本把写入带回冻结样本。
- 不调用付费模型、重新抓取外部素材、重置样本数据、上传内容或访问外部账号，除非用户明确授权目标、成本和影响。

## 变更规则

可以直接进行的工作：

- 只读检查参赛样本、评分证据和导演台状态。
- 在 `evaluation/` 内修复不改变评分口径、公开数据结构和参赛样本的局部问题。
- 在临时副本中安装依赖、启动样本和执行验证。

以下操作必须先向用户说明方案并取得明确同意：

- 修改或重跑任何冻结样本。
- 改变两种实验方式、约 30 分钟时间限制、模型集合、评分维度、权重或排名规则。
- 移动项目代码、改变根目录结构、修改公开数据结构或实机控制接口。
- 删除评分证据、有效样本或榜单产物。
- 发布视频、上传 B 站、部署到公网、提交或推送代码。

如果文档、实现和用户说明冲突，先列出冲突双方、影响范围和最小核验动作；由用户决定项目口径。不要用一个看起来更合理的版本覆盖另一个。

## 验证要求

验证应与改动风险匹配：

- 只改公开文案：检查禁用术语、中文通顺、分数和路径未变，并验证 `results.json` 与 `results.js` 一致。
- 只改静态榜单：检查 JavaScript 语法，并真实打开 `file://.../evaluation/index.html`，验证榜单、方式切换、差值、页面墙、双屏和图片放大。
- 只改导演台前端：检查语法，并真实验证模型/方式切换、URL 同步、评分浮窗、刷新恢复、保活、停止和失败提示。
- 改运行器或清单：除语法和安全检查外，执行 20 个样本的全量启动与停止检查；每项必须前端返回 200、状态进入 ready、停止回到 idle、前后端端口释放。
- 改进程、安全或缓存逻辑：补充端口占用、重复点击、启动超时、恢复失败、服务退出回收等故障场景。

无法完成某项验证时，报告未验证内容、原因和实际风险；禁止把“命令运行过”写成业务通过。

## 完成后汇报

最终汇报必须独立说明：

- 修改或创建了哪些文件；
- 哪些用户操作或页面行为发生变化；
- 执行了哪些验证，结果是什么；
- 哪些内容未验证或仍有风险；
- 是否修改参赛样本、分数、评分口径、目录结构或外部系统；
- 是否留下正在运行的作品或后台控制服务，以及如何停止。

不要自动提交、推送、部署、删除文件或创建定时任务。需要这些动作时，另行取得用户授权。

## 已知限制

- 当前目录不是 Git 仓库，不能依赖 Git 差异或提交历史判断改动范围；修改前后应使用文件清单、时间戳、内容哈希或定向对比。
- 实机导演台的缓存指纹当前不包含冻结样本的内容摘要。冻结样本不变时不影响使用；若用户明确更新样本，必须先清理对应临时缓存或更新缓存版本，再验证新内容。
- 播放器自身进入全屏时，浏览器可能隐藏父页面评分浮窗。录制时优先使用导演台的“进入全屏”，让作品和评分浮窗一起显示。
