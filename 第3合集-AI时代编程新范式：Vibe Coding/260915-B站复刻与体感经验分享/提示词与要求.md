### V2 评测协议

本文件中的产品任务语义对两种模式保持一致；变化只限于会话编排、权限隔离和证据记录。

- **one-shot**：一个模型对应一个唯一 Dev 会话和一条初始消息。禁止任何子代理、设计代理、架构代理和 Reviewer；允许同一 Dev 使用普通工具完成规划、自检和自修。Dev 第一次宣布完成后冻结，统一验收不向它反馈。
- **adversarial**：使用同一模型、同一 `high` 强度的两个持续会话：一个可写的 Dev 和一个只读的 Reviewer。固定执行 `Dev V0 → Reviewer → 原 Dev 修复 → 原 Reviewer 重审`，最多 3 次 Review。两个会话内部都禁用子代理；调度器只原样转交消息和报告，不参与设计、审查或代码修改。
- **工具适配**：不同工具只允许调整调用语法、权限开关、工作目录、会话恢复方式和日志采集方式，不得改变产品需求、交互目标、验收标准或给某个模型额外的设计建议。
- **目录与历史**：每个模型直接位于 `one-shot/<model>/` 与 `adversarial/<model>/`，两侧模型集合必须完全一致；每个模型只保留一个有效或按用户口径封账的 `run-XX`。无效试跑不归档在项目内，直接移除。Kimi K3、MiniMax M3、Grok 4.6 保留朋友按同一规则完成的既有结果。
- **正式重跑范围**：本轮不重跑 Kimi K3、MiniMax M3、Grok 4.6；这三个模型保留已有结果。其余模型按本 V2 协议执行。

### 形式：

1.一句话版本（主要）、对抗审查版本（次要）
2.在评价模型的时候，也要带上我们使用的真实体感
