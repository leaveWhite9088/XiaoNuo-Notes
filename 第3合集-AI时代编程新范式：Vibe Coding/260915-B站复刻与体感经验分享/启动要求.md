# 评测启动文档

## 说明

端口表覆盖 10 个模型 × 前端/后端 × one-shot / adversarial 两种模式，共 40 路分配。V2 本轮正式重跑其余 7 个模型；Kimi K3、MiniMax M3、Grok 4.6 保留已有 pilot 结果，不重跑。本文档只做一件事：**给每一路分配独立端口，防止冲突**。任务提示词另附，不在此重复。

## 端口规则

- 千位：`3` = 前端，`5` = 后端
- 个位：`1` = one-shot，`2` = adversarial
- 已避开常用端口区：3000-3002（CRA/Next/Express）、5000-5002（Flask/macOS AirPlay）、5500-5502（VSCode Live Server）、5900-5902（VNC）

## V2 启动约束

- 每个模型直接位于 `one-shot/<model>/` 与 `adversarial/<model>/`，两侧模型集合必须完全一致；每个模型只保留一个有效或按用户口径封账的 `run-XX`，无效试跑不在项目内归档。
- V2 使用本表中对应模型已有的端口分配。启动前必须关闭同一端口上的 pilot 服务，避免把旧服务误当成 V2 结果。
- one-shot 只启动一个 Dev 会话；adversarial 只启动一个持续 Dev 会话和一个持续只读 Reviewer 会话。两种模式均不得启动额外子代理。
- adversarial 的调度顺序固定为 `Dev V0 → Reviewer → 原 Dev 修复 → 原 Reviewer 重审`，最多 3 次 Review；调度器只原样转交内容。
